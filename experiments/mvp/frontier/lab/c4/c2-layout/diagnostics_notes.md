# Cohort and historical diagnosis provenance

The full CONTRACT including all Cycle 4 corrections, lab catalog safety code, C3 layout results and C3 Benders NOTES/BINDINGS were read. This subtask performed JSON reads and lightweight file/hash validation only; it ran no numerical jobs, replay, physics evaluator or checker. It wrote only in the Cycle 4 layout folder, with `PYTHONDONTWRITEBYTECODE=1`.

`build_manifest.py` first reads metadata summaries in the allowed V6 maps directory. It selects every `job.split == train` job with stage f60/f70/f80, independent of the constructor's pass result. It validates each input using `catalog.ensure_safe` before opening its bytes; metadata hashes must match the actual input hashes. The fixed development `medium12` set comes through `catalog.load_set`. f60, f70 and f80 each exist and contain 12 maps; medium12 adds 12 distinct maps. `MANIFEST.json` is a 48-row list, `ladder.txt` is the 36 D192 maps, and separate rung/list files each contain 12 approved paths.

V6 passes 5/12, 0/12, 0/12 on f60/f70/f80. Those counts describe our constructor built to pass. Its lift values are deliberately omitted from this manifest: it is not a lift benchmark. The four C3 warm primary maps were preselected from V6 passes; the whole-rung cohorts are not filtered by V6 outcome. Medium lifts refer to the D15 fixed-stow projection without later loads. No fresh baseline arm was run by this subtask, so none is inferred from old stored rows.

The historical failure extraction uses immutable score-row `method_metadata.trials`, not the shared mutable C3 trace directory. There are exactly four f60 and nine f70 failed maps. Every row has no returned candidate but records at least one replay-legal checked trial. `failures_c3.json` records each saved row path and SHA-256, every checked candidate's rule IDs, and later incomplete/screened restricted-pool rounds. Failing trial rule IDs are genuine full-check outcomes for those trial stows; restricted LP uncovered values and timed rounds do not prove physical impossibility. The “closest” diagnostic trial minimizes distinct failing rule count, then lifts, then order; it does not measure distance to feasibility.

The containership second-check rule has several constituent metrics. C3's D192 trial metadata saves only the parent rule ID, so it cannot identify area-to-flood on a particular D192 stow. C3 Benders' detailed D185 accepted witness does identify `containership_area_0_flood_mrad` as binding, with arrival headroom 0.000158135 m·rad, while rod securing passes. This is a reason to evaluate the real area metric in Cycle 4; it is not proof that the same metric binds on every map, or that GM is a necessary and sufficient substitute.

Verification: reproduced the builder successfully; 48 unique approved inputs, 12 paths per list, every actual input SHA-256 equals approved metadata where available, and 13 failed score rows have matching map/hash identities. No solver or full-checker pass is newly claimed here. Source evidence hashes are in `cohort_evidence.json` and `diagnostics_sources.json`.
