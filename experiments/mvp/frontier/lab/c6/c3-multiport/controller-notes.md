# Controller and reports

Run `controller.py --phase dev --out results/dev --max-workers 2` for the fixed six development maps and both arms. `--limit 1 --arms engine12 --max-workers 1` is a development smoke selection; the immutable policy core permits later expansion to all six in the same output, reusing only exact current configuration/run-key cache hits. Use one worker while another authorized numerical task consumes the second slot. The benchmark sentinel always reduces this controller to one busy worker.

After freezing, `controller.py --phase frozen --out results/main --max-workers 2` requires all32 manifest maps, matching FREEZE bindings and both arms. Frozen phase rejects smoke limits and single-arm selection. Development and nondevelopment evidence remain separate in reports.

The controller invokes local `run.py --worker` through `nice -n 5`, caps each arm/map at600 seconds from registered Popen launch, and sets one-thread numerical/native-worker variables plus absolute worker deadline/start variables. Only exact registered Popen children receive SIGINT. Direct workers are reaped before any timeout finalization. Registered native descendants must be absent before another launch; the360-second cleanup allowance is outside the censored600-second work clock. The guard records every poll, retains initial live/unknown evidence, archives previous audits when resumed, services other arm deadlines while draining, and interrupts remaining work if the benchmark sentinel appears. Malformed registrations and live/unknown descendants after grace stop new work. No process scans, pattern signals, unregistered PID signals, or native checker edits are used. Startup registrations can have a narrow unregistered-process race; the owning process/session remains the recovery mechanism if exact registered cleanup cannot be confirmed.

One global experiment lock prevents simultaneous controllers across output directories. A last-output ledger also checks exact registered unfinished jobs from a previous output after an interrupted controller. Worker/source/input identities, hashes, native/params/policy common bindings, and result run keys are checked. Source/config changes trigger cold reruns instead of reusing stale rows. Arbitrary or sentinel interruptions are archived and requeued, never recorded as resource timeouts.

A timeout preserves a pass or relaxed completion only from a concrete, consistent, original-instance checked checkpoint with all loads aboard and an absolute check timestamp within that launch's budget. Finalization uses saved native reports and the unchanged tier classifier; it performs no solve or fresh checker call. Missing/stale/late evidence yields an honest no-result timeout with replay unknown. Checkpoints are never counted as additional result rows. The timeout row is censored at600 seconds even if cleanup takes longer.

`controller-process.json` and immutable per-controller PID ledgers record selection, source hashes, policy, starts and PIDs. Worker ledgers add run keys, deadlines, signals, exits and reap times. `report.py` validates final rows and emits `summary.json`, `per-map.csv`, and `report.md` atomically. Completion tables use the exact frozen c5 aggregator after all-aboard evidence validation. Port/fill pass counts may combine ships; lift/restow/time means are kept within vessel/port/fill cells and labeled as own-T5-pass or paired-T5-pass means. Every relaxed completion includes hard rule occurrences and measured/limit breaches. External launch-to-observed-reap times come from matching owned ledgers; Capture time is retained separately, and any fallback is explicit per map. Timeout timing is always the declared censored cap.

Verification uses `test_controller_report.py` with standard-library mocks and synthetic native-report dictionaries: cleanup transient/expiry/history, malformed registration, exact descendant correlation, sentinel/deadline interaction, orphan overlap refusal, strict completion/run-key gates, timeout incumbent retention and rejection, no checkpoint double counting, within-cell paired means/tier counts, and external/capture clock separation. The controller dry run validates the real fixed manifest without importing native/numerical code or starting workers.

Timeout candidate selection uses the exact frozen `rank_analysis` within the highest retained tier: cargo retention, broken-rule count, breach, then lifts. It never selects a cheaper plan ahead of a smaller breach. Parent-owned manual smoke timings may be saved separately as `pids/manual-worker-PID.json`; report timing may read these explicit ledgers, while controller orphan cleanup scans only its own `worker-PID.json` registrations. Partial plans remain `best_safe_partial`, never completed tiers.

For a row without a completion, per-map reports may show the retained best ineligible candidate's analysis as `ineligible_candidate_diagnostic_only`. Hard-rule occurrences, breaches and diagnostic reasons are visible, but tier, lifts and parts stay empty and completion tables count no completion. This diagnostic evidence never enters lift or restow means.
