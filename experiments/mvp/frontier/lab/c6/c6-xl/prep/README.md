# Exact geometry-result cache for original producer C1

`geometry_cache.install()` wraps only the original search engine's `_nearest_cells` and `_oog_zones`; the first call runs the native implementation unchanged. Repeated identical inputs return defensive copies of that exact result. ClassFlow, placement masks, every original C1 screen and the checker remain unchanged. This module is preparation only and is not installed by the frozen solver or benchmark worker.

Keys include the complete ordered cell/slot/stack IDs, both complete slot-cell and slot-stack arrays with dtype/shape/bytes, all cell coordinate bits and stack-layout records. Donor keys also include the exact k type/value. OOG keys additionally contain the complete actual slot-centre array and the radius inputs computed through native parameter resolution and the native horizontal-overhang/radius formula. No identity-only or rounded geometry keys are used. Native method source hashes are asserted before installation, failing closed if the pinned implementation differs.

The original donor computation sorts distances from every slot to every cell; OOG zones construct every slot-pair distance. A producer that repeatedly rebuilds the same physical geometry need not repeat those calculations. This improves repeated initialization only; it does not speed up the first native call or weaken a cargo feasibility gate. A bounded eight-entry process-local LRU retains results; arrays stored internally are read-only, returned arrays are independent writable copies, and zone lists are newly allocated. No plan, assignment or solved ballast is cached.

Import after adding this `prep/` folder to sys.path, then call `install()` before original producer screens. Record this module's SHA256 with producer provenance. No source runtime file is edited. Tests compare cached outputs with the original methods, protect against mutation, force misses on coordinate/order/footprint/stack/k/radius changes, enforce the bound and verify original exception behavior. 18 targeted numerical tests passed in 0.79 s during an explicit CPU-slot handoff, with one numerical thread and nice -n 5 requested (macOS denied changing priority).
