## v5 review fixes: public API, frozen measurement preserved

All three P2 findings in `experiments/review/v5/rev-brief.md` are addressed in the new integration entry point `experiments.mvp.reader.public_brief`. Import its `VoyageBrief`, `plan_brief`, `read_brief` and `execute_brief`. The original `brief_planner.py` remains byte-identical as an internal historical experiment implementation: both running cohort manifests and the completed hero measurement freeze its source hash. Do not integrate that legacy API into the demo. Frozen runners and manifests have not been patched or restarted, and these tables still describe their original implementation.

- **Failed reading release gate:** any refused or malformed voyage sentence returns no plan, `passed=False`, `plan_released=False`, `status='needs_confirmation'`. Even another accepted hard sentence cannot bypass this whole-request gate. The planner must explicitly correct or remove the unresolved sentence and submit a new brief through the reader. Optional empty standing text remains allowed and still visits the parser. Original readings and accuracy are unchanged; no corrected meaning is invented. An old displayed plan must be labelled the previous plan, not a plan satisfying the new request. The general `refusal_flow` seam also blocks rejected voyage readings; its per-sentence approvals must never be combined with OR.
- **String overload:** the new API requires `VoyageBrief`; a bare string raises `TypeError` before any parser or planner call. Explicit restrictions belong in `voyage=(sentence,)`, so they cannot silently become standing preferences.
- **Reader-bound execution:** `read_brief` returns an immutable authenticated receipt, not a dictionary plus an independently mutable constraint list. `execute_brief(instance, receipt)` validates its full input/context binding and reconstructs hard constraints internally from exact validated readings. Sentence, role, binding status, reading and parser/adapter provenance are authenticated; each compiled constraint retains its source/provenance. Cross-process replay uses `export_checkpoint` / `load_checkpoint` with a dedicated application signing key (at least 32 bytes), stored outside checkpoints/logs and unrelated to provider credentials. An application must trust its checkpoint issuer. Minimal fabricated evidence, changed constraints/provenance, an omitted hard list, stale receipts and checkpoints for another input are rejected. Parser-free solver functions and the legacy executor are internal/baseline experiment facilities only.

**Rerun impact:** none of the current 60 cohort rows changes under these fixes. All 30 first-cohort and 30 second-cohort saved voyage readings are accepted, bind correctly, agree with the independent label and exactly match the runner's existing `hard_answers` reconstruction. Neither runner uses the string overload. The old executor's three exposed misuse paths are not used by these frozen measurements. No row was rerun, repaired or relabelled; the first cohort's impossible and interrupted rows remain unchanged. First/second frozen source hashes (26/28 entries), hero source hashes (59 entries), cohort/preregistration hashes and hero criteria/inventory hashes were verified unchanged. This is an integration fix, not a new benchmark of the release gate; a future measurement of the new API must be separately declared rather than relabelling these results.

**Regression verification:** **92 focused offline tests passed** (6.64 s). Tests cover all four review counterexamples, every refusal code, mixed accepted/unresolved sentences, explicit correction/removal, empty standing text, tampered or fabricated receipts, exact provenance, changed full input/context and authenticated replay. Provider, unavailable-reader and spend-accounting failures propagate rather than becoming ignorable standing readings. No Spark requests or new solver/checker runs were made for these orchestration fixes. The full checker and its admission/budget settings are unchanged; the existing fresh-audit cohort continues.
