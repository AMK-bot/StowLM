# Intake code and logic review

Reviewed the public API, deterministic validator, scoring and recording paths on 1 November 2026. The review made no paid calls and did not open sealed map cohorts.

The first review found four defects: partial nested DG declarations acquired unsourced defaults; unreadable null DG declarations could become non-DG facts; answering an identifier did not rekey its extraction group; and explicitly questioned unexpected identities were counted as silent errors. The revised implementation gates nested declarations, requires explicit no-DG/in-gauge evidence, rekeys identity corrections and excludes blocked unexpected identities from the silent-error count. Nested declaration, unreadable-null and identifier-answer fixes have dedicated offline regression coverage; scoring fixes were also inspected directly.

Follow-up review identified two edge cases, now fixed: later answers in the same batch follow corrected identities, and questions inside a list block that list's scored parent field. Direct inspection confirmed the identity map and symmetric scoring logic. The reviewer reran three targeted regressions (nested defaults, unreadable DG and identifier-plus-POD answers in one batch): all passed offline. The owner runs the complete intake suite as the final gate. No unresolved critical issue was found within this review scope.

The model supplies proposals only. The base load list supplies expected identities and validation limits, never replacement cargo facts. Human answers are explicit sourced declarations and go through the same validators. Before-answer extraction scores and after-answer scores are separate; the latter measure a model-plus-planner workflow. Canonical reconstructed-instance equality is stronger than field accuracy alone and is required for completed fixture cases.

Text provenance checks that the quote is present verbatim. It does not prove that the quoted words semantically entail every proposed value. Image quotes are model transcriptions labelled `unverified_transcription`; their correspondence to pixels cannot be proven by this validator. A plausible misread may therefore survive deterministic checks. The full stowage checker remains responsible for placement, aggregate stability and operational legality.

The development and held-out examples are two small synthetic packets with planted traps, not a representative freight-document benchmark. Their measurements do not establish generalization, real-customer accuracy or production readiness. Ground-truth planner answers must never be presented as model extraction accuracy. Recorded answers retain their recorded label; oracle readings remain distinct from paid Spark recordings.

## V2 review before implementation freeze

Reviewed `validation.py`, `provenance.py`, `__init__.py`, `measure.py` and `evaluate_v2.py` as code only. This review did not read the fresh held-out inputs, truth, recordings or scores, and made no model call. Development recordings and independent synthetic provenance adversaries were the only allowed examples.

CSV evidence now binds each assertion to its source document, physical container row, correct column and JSON annex path. A value merely occurring elsewhere is insufficient. The validator requires this evidence before accepting a CSV field, stores the actual decoded cell and coordinates, and uses the helper's canonical value. Rounded weight presentation is reconciled with exact EDI only within the same row's explicit last-digit precision interval; arbitrary nearby values remain unsupported. Twenty independent helper tests passed, including wrong-row/column/value/null cases and large-integer precision adversaries.

Safety checks run on available prerequisites before the complete Container construction: missing unrelated fields no longer suppress mass, rating, tare, IMDG, yard, rotation or ship-capability findings. A planner may explicitly replace a questioned nested field's ancestor, including withdrawing a false DG declaration; that replacement is recorded and revalidated. No parent replacement is inferred silently.

The scorer keeps original extraction and planner-assisted results separate. Its null-ancestor traversal supports false DG declarations, and its field-level blocker covers nested lists in both directions. Aggregation weights counts by actual field/row totals rather than averaging case percentages. Clean controls, planted traps, assembly equality, model dollars and recorded model seconds have separate labels. Aggregate reading time is the sum of packet times, not a per-packet latency claim.

Two evaluation issues were reported to the owner before freeze and confirmed fixed by code inspection: the held-out command requires and verifies the source freeze, input manifest and individual input file hashes before the loop and each case, including resumes; truth-list traversal handles missing indices with an explicit parent correction and catches malformed or out-of-range paths. Four isolated temporary-fixture freeze tests were added by the owner and inspected without accessing the real evaluation cohort. These are evaluation guards, not model-output corrections; no fresh held-out example was consulted to identify them. No unresolved critical finding remains in this review scope. The owner runs the complete offline suite before freezing the implementation.

The earlier image and prose limitations still apply. CSV cell verification does not establish that a model transcription matches an image. The new synthetic cohort remains a small development-scale benchmark; any reported success is specific to its frozen packets and planted traps, with no real-customer or production generalization claim.

## V6 code4 repairs

This section supersedes the earlier provenance/authority conclusions. The five findings in `experiments/review/v6/code4.md` were reproduced with independent synthetic inputs before repair; original held-out inputs and retained scores were not used to design the fixes.

1. `test_review_security.py` reproduced quote/value substitution, wrong-row evidence and imperative stowage instructions, plus unverified image acceptance. Facts now require deterministic row/field/value binding or an explicit planner confirmation. Nonempty special stowage always yields a blocking reader referral, including dotted list entries and subsequent planner answers. Image sidecars, duplicate prose JSON keys and fake planner document origins cannot authenticate values.
2. The same file reproduced a forged `duplicate_resolutions` through `read_documents` and directly through validation. Model proposals reject extra keys. Duplicate authority and fact confirmations live outside the model proposal, in the receipt context produced by the public answer API. Genuine confirmations survive JSON round trips; ambiguous question-id delimiters cannot redirect an answer to another cargo row.
3. `test_csv_conflicts.py` initially reproduced 11 failures; duplicate JSON keys added two observed failures. All declarations are collected before proposal matching, including unmentioned CSV sources, repeated columns/rows, annex paths, null ancestors and ambiguous identities. The final independent CSV/provenance run passed 45 tests. A separate global-normalization regression failed before repair for equivalent `20` and `20.0` declarations; schema normalization now avoids that false conflict while independent source conflict flags remain blocking.
4. `test_measure_security.py` exercises the public scorer, raw substitution, exact request/capture binding and canonical paths. Frozen scoring cannot reach validation or persistence when verification fails, including `save=False`.
5. `test_evaluate_v2.py` pins the effective active-reader prompt, transitive project imports, cargo/IMDG schema and data, catalogue, lockfiles and Python/Pydantic runtime. Changing any pinned dependency fails before recording or scoring. Seven new P2 regressions failed before repair; the final targeted P2 run passed 19 tests.

No new paid call was made. The v2 first scores and original freeze manifests remain immutable historical records; those old freezes intentionally cannot authorize scoring with repaired source. `review_v6.py` is an explicit, separately labelled retrospective audit of already-scored v2 recordings: it first checks whether validated behavior changed, evaluates changed cases only as spent-data development replay, verifies every original cohort artifact stayed byte-identical and writes `review_v6_results.json`. It cannot record a model call. It also refreshes the separate demo's validated artifacts without changing their public file shapes.

Final verification: 149 admitted offline tests passed (98.49 seconds). The separately recorded retrospective replay changed fields from 1096/1155 to 1071/1155 and exact rows from 39/62 to 33/62; traps remain 21/21 and silent wrong values zero. After cargo answers, 61/62 rows are exact; one under-deck request correctly remains behind the reader gate. Two completed replay cases match their bases. The demo remains complete with 13/13 exact rows and base hash equality. No source was changed after this replay; no new paid call was made.
