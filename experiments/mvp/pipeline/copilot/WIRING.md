# Tool wiring

`ToolSet` lazily loads the landed `pipeline.explain.explain_box`, `pipeline.sandbox.try_move` and `pipeline.lattice.lookup` APIs. Explanation defaults to deterministic evidence templates or labelled recorded explanations. A lattice miss returns no plan, including while the hero catalogue has no suitable entry. Explicit unavailable adapters remain injectable. No adapter makes a paid call.

Every proposed reading exposes all standing and voyage rows. Re-reading an earlier confirmed sentence must preserve its canonical parsed answer, status, binding role, source sentence and stable parser/model/adapter identity. Request IDs, timing and spend metadata can change. Any semantic or provenance drift blocks the entire draft, and confirmation repeats that check. Nonempty standing text blocks confirmation unless the reader explicitly enables its supported preference, matching the runner gate. Model-written refusal reasons remain inside the authenticated receipt; outward reasons use deterministic refusal-code templates.

`replan(reading_id)` and `try_ladder()` submit detached work to `JobManager` and return a running job immediately. This includes injected replanners. Tests can explicitly supply an inline manager through the host-only `job_manager` constructor argument. The model cannot choose a manager or confirm a reading.

The worker authenticates the confirmed reader receipt, invokes the backend, runs the full checker and independently audits the confirmed instructions. `wait_replan(job_id)` polls without waiting or running a checker. It publishes the prepared result only when the current instance, plan, reading and generation still match the submission. A changed state makes the result stale. Native work is not force-cancelled.

Native jobs and synchronous checker, sandbox, lookup and explanation consumers share the process-wide guard. A busy guard returns a running response instead of waiting. While a ToolSet has an active job, these consumers return its progress or completed result. Context exposes the active job, authenticated confirmed rules and current unconfirmed reading without native checking.

After an impossible instruction, `list_limits()` includes that current reading's arithmetic proof and software-owned alternatives. Candidate expansion reuses the reader proof's declared same-family search and static arithmetic, bounded by the host's `alternative_limit` (default four). An alternative remains explicitly `unchecked`/`screen_only` until its own stored candidate passes a fresh full checker and every hypothetical and previously confirmed instruction. Several independently checked options can be returned, each with an evidence ID and a checker-count cost reference so Spark can rank them. Lift costs appear only when measured in that report. A response with no checked alternatives says so explicitly. Choosing an alternative requires a new reader submission and planner confirmation; negotiation never applies it automatically.

The default sandbox verdict is diagnostic and never installs a plan. Its candidate is independently audited against confirmed reader instructions, and a failed instruction audit prevents a legal verdict even when the base checker passes. Invalid targets return an explicit input rejection without calling the full checker.

Backend budget parameters are not total wall-time limits. The small-map engine retains constructor floors, and indivisible replay/checker operations can overrun their requested stage budgets. Background execution keeps the conversation responsive while preserving these native semantics.
