# Test reference API audit (29 Oct 2026)

Read-only source review; no solver jobs were run by this audit.

- Run `stowage.planner.run_planner(planner, instance, seed=0, time_limit_s=budget, allow_repair=False)`. It performs finalization, full checking, provenance binding and measured pipeline timing. Its default repair is enabled; suppress it for honest own-plan reference rows. `eval.harness._evaluate` does not disable repair for these planners.
- Planners: `stowage.solver.twostep.TwoStepPlanner`, `stowage.solver.scalable.ScalableSolver`, `stowage.solver.exact.ExactPlanner(num_workers=1, max_nodes=...)`. Two-step/scalable need the finisher; exact owns ballast and its accepted terminals already underwent the finisher, full checker and configured-engine replay. `finalize` retains existing ballast safely.
- Exact `solve_exact` has a hard parent wall deadline including native calls, with an owned worker and validated incumbent checkpoints. `time_limit_s=60` caps the solve; the outer full checker adds measured time after that deadline. `OPTIMAL` means weighted-lift optimality within `engine_model_weighted_lifts` / public-engine domain; `physical_domain_optimality_certified=False`, continuous margin optimum unproved. Preserve these scope fields.
- An exact timeout can carry a previously validated incumbent. Display it as **best-found (timeout)** with the full outer checker verdict; absence of a plan is **no validated incumbent**, not an optimal/best-found objective. `PlannerResult.shippable` requires `status == "ok"`, so checked timeout incumbents are excluded from the existing harness's objective-pair population via `_objective_eligible`, although `_passed(..., population="own")` can include them in the own checker-pass rate. Never promote `shippable` manually or omit it to trigger historical-record compatibility.
- `stowage.bounds.lower_bound(instance)` is deterministic counting, without timed search. Bounds add disjoint lift types, and take maxima for overlapping bounds. A lower bound is work every possible solution must pay; matching it with a passing plan can certify the corresponding cost (see module validity notes and `stowage.solver.exact_oracle`). `L=0` is reported as no informative gap certificate by this API. Bounds have no plan and thus no checker/finisher verdict.
- `report.count.relocations` means yard rehandles. `restow_lifts` and `hatch_cover_lifts` are current-call moves; `count.future` contains projected later restows/covers. Preserve projections separately. `weighted_nonproductive` uses the instance's objective weights and future projections; do not substitute a raw sum.
- For D68 aggregates and `paired_comparison`, records need `instance_id`, exact `input_sha256`, `spec_key`, `split`, `rung`, `result`, `report`, `shippable`, `report_binding_valid`, and `timing.total_s/plan_s`. Pairing rejects different identities/hashes and duplicate IDs. Objective pairs require both eligible passing own plans; default population excludes repaired plans. Report n_pairs/n_excluded.
- CP assignment already uses one worker. Pin BLAS/OpenMP/Accelerate thread environment variables to one before imports. Run all heavy stages sequentially under `nice -n 10`; this audit launches no competing jobs.
- Freeze-switch assertion must be false in the execution path. Source edits from other executives may happen during the campaign: record source fingerprints per result and flag drift; never silently attribute changed code to an old version snapshot.
- The wave-2 run contract is model-focused. Classical reference artifacts can keep its `manifest.json` + per-instance `result.json` layout and place the full report beside the result. Do not invent neural decode traces or label solver artifacts as StowLM.
